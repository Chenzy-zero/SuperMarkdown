# 第一轮技术选型与原型结果

日期：2026-11-14。

本文保留早期验证结论。当前应用已迁入 src/app/，0.2.0 已实现真实保存与恢复，最新能力及验证见 [保存与恢复](saving-and-recovery.md)。下文的“未实现”描述对应当时的原型状态。

## 结论

本轮采用 Electron 45.3.2 运行 Windows 桌面原型，使用 Vditor 4.0.1 作为候选可视编辑器；版本与依赖完整性记录在根目录 pnpm-lock.yaml。

原型证明了应用统一管理文档与撤销历史的路径可行，也证明了候选编辑器原生往返转换不等于原始内容保留。Vditor 尚未确定为正式内核：光标映射、真实中文输入法及更广泛的语法兼容仍需验证。

本次后续修订已接入真实工作文件夹浏览，以及 Markdown / 其他文本文件的分流打开。代码文件的语法高亮与语言风格化显示按补充需求留到下一期。

用户试用反馈后的宽窗口、链接、目录操作、分屏与启动方式调整，见 [本轮界面修正与验证](usability-fixes.md)。基础验证仍为 40 项；2026-11-15 加入快捷关闭、统一留白和可调分屏后，最新界面回归合计 112 项通过。

## 本轮验证问题与实现

原型位于 experiments/editor-spike/，既支持内置示例，也支持读取真实本地文件及实际创建空白 `.md` 文件。编辑修改仍仅保留在内存中，正式文件保存与恢复尚未实现。

1. **跨模式撤销**：安装包源码 src/ts/undo/index.ts 为各编辑模式分别维护历史。因此原型由应用持有每篇文档的 Markdown 快照历史，可视编辑和源码编辑共同提交修改；切换模式本身不产生一条编辑记录。
2. **无编辑往返**：切换视图时不主动以编辑器重新导出的文本替换文档，避免仅查看就改写文件内容。
3. **原始片段保留**：原生导出会把样本的 `~~~mermaid` 围栏改为反引号围栏，并去除公式行尾空格。原型在普通正文修改后恢复受保护片段的原始文本，并要求从源码模式修改这些片段。
4. **本地资源**：编辑器、中文语言包、图标和解析器均从本地依赖加载；检查中禁止远程请求，实际记录为零。
5. **文件夹与文件类型**：原生对话框选择本地文件夹；主进程通过 preload 提供文件读取与空白 Markdown 创建接口。目录按需展开并可刷新，按内容识别可读取的文本，支持无扩展名文本。Markdown 默认可视打开，其他文本文件使用普通文本区，代码和 HTML 内容不作为页面执行。文档身份按真实文件路径区分，已打开文件复用标签页。
6. **分屏视图**：双文件并排使用各自的文档与历史；预览源码同步则让两个编辑视图使用同一份文档快照历史。右侧编辑器仅管理视图模式、光标及滚动位置，避免另存一份可分叉的文档内容。程序刷新另一侧时不主动移动焦点。

编辑器源码参考：[Vditor 撤销实现](https://github.com/Vanessa219/vditor/blob/master/src/ts/undo/index.ts)、[Vditor 文本导出](https://github.com/Vanessa219/vditor/blob/master/src/ts/markdown/getMarkdown.ts)。本轮结论以安装的 4.0.1 源码及本地实测为准，链接中的 master 可能继续变化。

## 检查结果

运行 `pnpm prototype:check`：检查在真实 Electron 页面中运行，使用 contenteditable 输入、源码文本区、主进程文件读取接口及应用的切换和历史路径。最新结果为 40 项检查全部通过，退出码 0。

- 编辑器载入、本地图标、标题/粗体/表格实际渲染。
- 未编辑时的模式往返保持文档原文。
- 可视输入同步到文档，源码输入同步到可视区域。
- 跨模式撤销、连续重做、分支编辑清除旧重做记录。
- 文档标签切换保留内容。
- 修改普通正文后，样本中的 Mermaid 围栏、行尾空格和公式片段保留。
- 普通代码块中的公式示例不会误判为独立公式；可视编辑破坏受保护片段时保留原文并提示使用源码模式。
- 检查结束恢复干净示例。
- 真实目录与子文件夹浏览，Markdown 大小写扩展名识别、默认可视打开，以及重复文件标签页复用。
- TXT、JS、HTML、未知扩展名和无扩展名文件纯文本打开，Markdown 符号保持字面显示，HTML 中的脚本不执行。
- 查看 CRLF 文本不产生修改，纯文本撤销/重做保留换行，切换文件与刷新目录保留窗口内的修改。
- UTF-16 中文与 GBK 兼容文本读取；二进制筛除及选定目录范围检查。
- 文件浏览与窗口内编辑不改写磁盘原文件；从目录实际点击代码文件进入纯文本视图。

自动检查在项目内部创建临时样本目录，文件读取使用真实接口；为避免弹出系统对话框，自动运行时直接提供该目录作为选择结果。原生对话框的人工交互没有由这些检查覆盖。

报告与窗口截图位于 .prototype-artifacts/report.json、.prototype-artifacts/editor.png 和 .prototype-artifacts/plain-text.png，可重新生成，不纳入版本控制。

另有 5651 字符的纯文字长文样本，记录过约 11 ms 的同步渲染调用。本数字仅用于定位后续测量点，不包括首次启动、完整绘制、输入法延迟或完整图文表格样本，不构成性能验收结论。

## 尚未通过的验证与未实现范围

- **定位**：当前光标映射是文本匹配的启发式实现，尚不满足完整首版要求。重复文本、包含格式标记的段落和选区可能定位错误；需要建立可靠的源码位置映射。
- **中文输入法**：自动检查输入了中文文本，但没有证明真实拼音输入法的候选选择、组合输入、撤销及快捷键行为正确。
- **语法保护**：目前仅验证顶层 Mermaid 围栏与独占行 `$$` 公式。列表/引用中的嵌套块、行内公式、其他扩展语法和不完整语法仍需扩大样本。
- **表格**：已验证真实渲染，可试用候选内核的编辑操作；尚未完成全部行列菜单、键盘行为及兼容性验收。
- **文本读取边界**：原型暂支持 UTF-8、带 BOM 的 UTF-16 及 GB18030/GBK 兼容文本，单文件上限 20 MB；不遍历符号链接或目录联接，未实现打开文件夹状态持久化。
- **图片、文件与交付**：文件保存、图片落盘、草稿恢复、外部文件内容变更监听、查找替换、安装包等仍属于正式实现任务。刷新目录只更新目录列表，不代替已打开文件的内容变更监听。
- **平台**：本次只在当前 Windows 环境运行；不能据此声称已覆盖 Windows 10/11 的目标版本与配置。

## 下一步

先用原型评估中文输入、选区及表格体验；补齐位置映射和语法兼容验证，再确定正式编辑内核。应用层文档状态与编辑器视图保持边界，避免文件、恢复及历史逻辑被某个候选内核绑定。

本次目录选择与跨进程调用参考 [Electron dialog](https://www.electronjs.org/docs/latest/api/dialog) 和 [Electron IPC](https://www.electronjs.org/docs/latest/tutorial/ipc)，文本解码参考 [Node.js TextDecoder](https://nodejs.org/api/util.html#class-utiltextdecoder)。
