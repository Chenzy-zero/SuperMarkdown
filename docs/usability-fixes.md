# 本轮界面修正与验证

本轮针对用户提供的三张截图和八项反馈更新原型。

本文件保留界面迭代历史。0.2.0 已迁入正式应用目录并补齐保存与恢复，当前行为见 [保存与恢复](saving-and-recovery.md)；下文的原型保存边界对应历史版本。

| 反馈 | 处理结果 |
| --- | --- |
| 放大后右侧大片空白 | 编辑滚动区占满正文区域，阅读宽度由对称内边距控制；滚动条位于正文区域右边缘 |
| 左侧字体小 | 文件目录、大纲和目录分组字号调整为 15px，相关按钮字号同步增大 |
| 超链接目标与跳转 | 按后续澄清，在鼠标指针右下方以浮层显示实际目标，随指针移动并在离开链接或滚动后隐藏，窗口边缘自动避让；相对地址按当前文档解析，本地文本内部打开，网页由默认浏览器打开 |
| 希望 Ctrl+Shift+Z 切换源码 | 检查后保留原来的 Ctrl+Shift+M；Ctrl+Shift+Z 保持重做，避免重做与模式切换争用 |
| pnpm 启动失败 | 新增根目录双击入口，直接使用已安装的桌面运行文件；开发命令的终端与目录前提写入 README |

| 大纲跳转标题被遮住 | 留出 64px 顶部空间，取消旧的菜单延迟任务并隐藏旧菜单；切换文档恢复各自滚动位置 |
| 表格浮动菜单太小 | 按钮高度调整为 34px、图标 18px、输入框与菜单字体增大；菜单根据实际尺寸重新定位 |

## 快捷键依据

微软官方的 [Visual Studio 快捷键表](https://learn.microsoft.com/en-us/visualstudio/ide/default-keyboard-shortcuts-in-visual-studio?view=vs-2022) 将 Ctrl+Shift+Z 列为 Edit.Redo；[VS Code 官方默认绑定](https://github.com/microsoft/vscode-docs/blob/main/build/keybindings/doc.keybindings.win.json) 也包含该重做绑定。本工具原有代码已将其作为重做别名，因此本轮不将它改成切换模式。

标签页菜单范围参考 [Notepad++ 官方用户手册](https://npp-user-manual.org/docs/views/)，采用关闭、批量关闭及路径操作的常见交互。

## 复现与回归

修复前，界面检查测得：可用正文宽度 1696px，实际编辑区仅 835px；目录字体 12px；大纲目标标题距离滚动区域顶部不足 1px。针对这些具体症状建立回归检查，再修改样式与跳转逻辑。

启动入口此前通过 `启动SuperMarkdown.cmd --verify` 完成 63 项检查，退出码 0；该轮从项目之外的临时目录启动，并将 PATH 缩减为 Windows System32，确认入口不依赖普通终端中的 Node/pnpm 命令。链接浮层改为跟随鼠标后，使用 `pnpm prototype:ux-check` 完成 68 项检查，全部通过，退出码 0。

本次宽窗口检查测得：可用正文区域与编辑区均为 1668px，目录字号 15px，浮动菜单按钮高度 34px；标题跳转后距顶部约 64px，原先可见的浮动菜单已隐藏。

覆盖鼠标右下方的链接提示、指针跟随、离开与滚动隐藏、窗口边缘避让，以及点击原链接、本地中文编码路径、父目录明确链接、网页分流、标题定位、重做快捷键、标签关闭、取消/放弃修改及关闭全部后的重新打开。网页打开在自动检查中记录发送给系统的目标，不实际启动浏览器；原生浏览器与资源管理器的用户交互仍可手动试用。

检查报告及截图位于 .prototype-artifacts/，可重新生成。批处理入口使用 ASCII 内容与 Windows CRLF 换行，避免普通 CMD 的脚本解析兼容问题。

## 2026-11-15：目录操作与分屏

- 顶部格式按钮的悬停提示改为独立浮层，显示在按钮下方并避让窗口边界；不受编辑区域的溢出裁剪影响，两侧工具栏均适用。
- 目录中的文件支持右键打开、在右侧打开、新建 Markdown、复制完整路径、在文件夹中显示及刷新。子文件夹可右键选择新建位置；侧栏按钮默认在工作文件夹根目录新建。
- 新建操作实际创建空白 `.md` 文件，省略扩展名时自动补全；采用排他创建，避免覆盖同名文件，并拒绝路径字符与 Windows 保留名称。
- 显示布局支持单文件、双文件并排、预览源码同步；标签页可右键移到右侧。双文件分别编辑，同篇 Markdown 则固定左侧可视编辑、右侧源码，两边均可输入并共用历史。

通过根目录启动入口执行最新验证：从项目外临时目录启动，PATH 仅保留 Windows System32，94 项检查全部通过，退出码 0，无远程资源请求。新增检查覆盖提示完整可见、文件与目录菜单、真实子目录文件创建、同名保护、路径名称校验、右侧纯文本及可视编辑、两侧内容独立、同文档双向同步、输入光标保留、两侧撤销重做及退出分屏内容保留。

隐藏验证窗口中的 `focus()` 不保证触发完整的原生焦点事件，因此跨侧编辑检查同时重放用户点击正文的指针事件。真实中文输入法及原生系统对话框仍需要人工试用。

## 2026-11-15：快捷关闭、统一留白与可调分屏

- `Ctrl+W` 关闭当前文档，复用原有未保存提示。双文件时按当前侧关闭，同文档两种视图一起关闭；没有文档时不退出应用。确认框打开时重复快捷键不会跳过确认。
- Markdown 可视编辑和源码共用居中阅读宽度及左右留白规则；按当前窗格宽度自适应，纯文本文件继续保持普通文本编辑的布局。
- 两种分屏布局提供 8px 宽的可拖动分隔条；常规宽度下每侧至少保留 280px，较窄区域允许等分。双击恢复等宽，键盘方向键可调整比例，切换布局保留本次窗口的比例。拖动不修改文档内容。

新增回归覆盖快捷关闭的未保存保护、取消及确认、关闭右侧文件、空窗口，以及单文件和分屏留白、拖动两端边界、窄区域适配、键盘调整、双击重置与比例保留。最新完整界面回归为 112 项全部通过。

## 当前边界

现有原型支持创建空白 Markdown 文件，尚未实现将正文修改保存回文件。关闭有修改的标签页时，提供返回文档或明确放弃修改两个选项，并说明需要先自行保留内容；不会展示尚未实现的保存按钮。旧的已打开窗口不会自动加载本轮修改，重新打开前需要保留其中的未保存内容。
