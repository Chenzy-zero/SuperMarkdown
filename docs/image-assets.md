# 图片资源管理（Issue #5）

> 状态：Tauri 端到端实现；支持 **插入本地图片…**、**Ctrl+V 截图粘贴**、**资源管理器图片拖入**、持久化与离线显示。另存为资源迁移/清理仍由 #19 跟进；截图粘贴与系统拖放的 Windows WebView2 真机验收分别见 #6/#7。

## 用户操作

1. 打开或新建 Markdown 文件。未命名文档点击“插入图片…”时先进入另存为，取消则不生成资源。
2. 点击文件名工具栏右侧的“插入图片…”，在 Windows 原生文件选择框选中 PNG、JPEG、GIF 或 WebP。
3. Tauri 将图片写入 Markdown 文件所在目录的 **`<文档名（不含扩展名）>.assets/`**，并在光标处插入相对 Markdown 引用，例如 `![图片](My%20Notes.assets/1d812ed5-4ec2-4292-a992-d56974234517.png)`。
4. 按 **Ctrl+S** 保存 Markdown 内容。关闭后重新打开，同一文件所在目录下的资源由受控 Tauri 命令离线读取并渲染。
5. 或者在 Markdown 编辑区域按 **Ctrl+V** 粘贴截图，支持 Windows 截图工具复制的 PNG 等图片。含图片的剪贴板数据仅在当前 Markdown 编辑区被拦截；普通文字、查找框、菜单和 TXT/代码文件的粘贴按原行为处理。剪贴板图片大小超过 8 MiB 或格式不受支持时显示错误，不修改 Markdown。
6. 也可从 Windows 资源管理器将一张或多张 PNG、JPEG、GIF、WebP 图片直接拖入 Markdown 编辑区，按拖入顺序插入到鼠标所在的光标位置；同一批次中的普通文本文件继续按原有方式在对应窗格打开。未命名文档会先要求保存，取消不会导入图片。图片超过 8 MiB、文件头无效或为符号链接时拒绝导入。

**安全的写入范围**：已经通过文件对话框打开 / 保存的 Markdown 文件的同级专属目录，前端**不能指定任意目标路径**。如果用户当前位于可视编辑模式，插入前转为源码模式以避免破坏现有结构；同步分屏则在右侧源码插入，左侧仍可预览。插入 Markdown 引用本身记为一条 Undo；图片作为单独磁盘资源，不会随 Undo 自动删除。

**拖放事件分工**：Tauri `WindowEvent::DragDrop` 提供操作系统授予的本地路径；DOM `drop` 事件只负责阻止 WebView 默认导航、记录实际鼠标坐标与左右窗格。Tauri 模式下 DOM 不再处理 `DataTransfer.files`，文件只由原生队列处理一次，避免一次拖放重复打开/导入；Electron 遗留验证宿主继续由 DOM 事件处理。图片路径只以一次性内存 token 暴露给渲染器，Rust 重新检查普通文件、大小和图片魔数，再复用 `import_bytes` 的文档级 `.assets` 原子写入逻辑。

## 数据约定

| 内容 | 规则 |
| --- | --- |
| 文档 | `/project/设计稿.md` |
| 资产目录 | `/project/设计稿.assets/` |
| 文件名 | UUID v4 + 通过文件头识别的扩展名（`.png`/`.jpg`/`.gif`/`.webp`） |
| Markdown 引用 | URL 百分号编码的相对路径，按 UTF-8 编码含中文、空格等字符 |
| 最大体积 | 单张图片 8 MiB；过大或空文件拒绝 |
| 安全格式 | 仅 PNG、JPEG、GIF、WebP；拒绝 SVG、HTML、PDF 等 |
| 导入方式 | 文件选择框调用 `choose_image_and_import`；剪贴板调用 `import_image_bytes`；原生拖放通过一次性 token 调用 `import_dropped_images` |
| 显示方式 | `read_image_asset` 限制在当前 Markdown 资产目录下，前端将可信图片字节转换成 `data:` URL，不授予任意 `file://` 访问 |
| 去重 | 暂不去重；相同图片多次插入生成两个不同 UUID 文件，永不覆盖已有文件 |

## 安全边界与失败策略

- 仅使用 `WorkspaceState.opened_files` 中的文件 key 查找目标 Markdown 文档。TXT、代码文件及未知 key 均拒绝。文档已不存在、真实路径变化、资产目录是符号链接/普通文件时拒绝操作。
- 前端传来的二进制内容经过文件头校验，不能由客户端任意指定 MIME 类型或目标后缀。加载资产时再次检查文件头、UUID、扩展名、目录及文档身份。
- 导入先创建 UUID 命名的 **临时文件**、写入并同步到磁盘，再以不覆盖现有文件的方式发布为最终路径。操作失败清理临时文件，错误不会修改现有 Markdown 或覆盖旧图片。
- 仅当导入成功时才修改 Markdown 缓冲区。Markdown 修改仍使用原有 `DocumentHistory`、保存基线、冲突检查和草稿恢复机制。异常退出时，未保存 Markdown 可能通过草稿恢复；已导入但未引用的图片需由后续资源清理功能 #19 管理。
- 读取时只接受形如 `<当前文档名>.assets/<UUID>.<支持格式>` 的路径，拒绝父路径跳转、绝对路径、其他文档的目录、链接到资源目录之外的符号链接和超大文件。
- 图片内容使用受控字节接口渲染，绝不扩展 Tauri `capabilities` 为任意磁盘访问。磁盘重定向与跨进程目录替换属于更广泛的本机文件系统竞争风险；主要防线为规范路径、普通文件检查、符号链接检查和最终写入前复核。

## 已知限制与后续

- **另存为/迁移文件**：目前**不会自动搬迁图片资源目录，也不会重写引用**。另存为到别的目录或改变文件名后，应手动同时复制原来的 `.assets` 目录到新文件所在位置，保留 Markdown 引用所指的目录名；自动更新引用和清理属于 #19/#17。
- **Ctrl+V 截图粘贴已在 #6 实现**：使用用户触发的 ClipboardEvent 获取图片字节，调用 #5 的受控导入命令，不轮询剪贴板、不获取读剪贴板权限、不联网。对纯文本、HTML、搜索框和无图片剪贴板不拦截。真实 Windows 截图工具与 WebView2 行为需在 #3/#6 真机验收。**OS 图片拖入已在 #7 实现**：Tauri 原生事件处理绝对路径，DOM drop 提供窗格/光标位置；非图片继续走文本打开流程，图片通过一次性 token 在 Rust 端复核后调用同一受控资产服务。多图按拖入顺序批量插入并作为一条 Undo。真实 Windows WebView2 文件拖放仍需 #3/#7 人工验收。
- 文件头检验不是完整图片解码器，损坏图片可能写入成功但显示失败；浏览器解码失败时不会执行脚本。
- 初始加载最多尝试还原前 128 张管理图片；大量图片的懒加载/内存治理后续优化。
- Electron 0.4 遗留验证宿主没有对应的 Rust 桥接能力，该入口自动禁用；主线目标是 Windows Tauri。
- 必须在真实 Windows/WebView2 中检查中文和空格路径、只读目录、资源目录被替换、取消导入、编辑器切换、双窗格预览及离线重新打开。不能用 CI 编译成功替代真机 UI 验收。

## 验证方式

自动化：`cargo test --locked --manifest-path src-tauri/Cargo.toml` 测试图片导入/读取/路径分类/拒绝越界/类型与大小校验；`pnpm test` 额外验证剪贴板图片筛选、文本粘贴保留、原生/DOM 拖放单一处理路径、左右窗格目标、批量插入顺序、CRLF 光标和单步 Undo。Windows CI 还需构建 NSIS。

建议测试样本：`中文 笔记.md`、含空格的同级目录、同名重复插图、PNG/JPEG/GIF/WebP、非图片伪装、超过 8 MiB、取消选择、重启后断网预览、Windows 只读目录与目录符号链接。
