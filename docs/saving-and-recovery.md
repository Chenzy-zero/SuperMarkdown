# 文件保存与恢复

当前应用源码位于 src/app/，0.2.0 开始提供真实的保存闭环。0.1.0 Release 保留为历史验证版本，不会被替换为不同内容的安装包。

## 已实现行为

- 新建未命名 Markdown，打开单个文本文件或工作文件夹。
- Ctrl+S 保存当前文档；未命名文档选择保存位置。Ctrl+Shift+S 另存为，保留原文件。
- 可视、源码及同步分屏共用同一份文档和保存基线。保存不清除撤销历史，撤销到与磁盘不同的内容时重新显示未保存标记。
- 保存期间继续编辑时，只有提交给磁盘的快照被标记为已保存；后续输入保持未保存状态。
- 标签页关闭、Ctrl+W 和系统窗口关闭均使用保存、不保存、取消三个选项。保存失败或取消保存位置不关闭文档。批量关闭一次确认，选择保存时逐篇保存，任一失败则保留打开状态。
- 定期写入未保存文档的恢复草稿，包含未命名文档、原保存基线、编码和文件身份。重启后提示恢复或放弃，恢复本身不改写源文件。
- 自动检查外部文件变化；干净文档载入磁盘新内容，有本地修改时提示重新载入或另存。原文件不存在时保留内容并转入另存为。

## 写入过程

文件服务持有经打开或系统保存对话框确认的路径；页面不能直接提交任意保存路径。保存前比较文件字节的 SHA-256 指纹，拒绝基于旧内容直接覆盖外部修改。

同一路径的保存按顺序执行。先将全部内容写入同目录唯一临时文件，刷新文件数据并关闭，替换前再次核对指纹，最后重命名替换目标。临时文件写入失败时原文件不会被截断；替换后重新读取核对结果。该过程降低部分写入和通常并发编辑的风险，不声称跨所有文件系统或与其他程序之间提供事务级原子比较交换。

原文件保存保留 UTF-8 的 BOM 状态、带 BOM 的 UTF-16 大小端编码、GB18030/GBK 兼容编码及原有 LF/CRLF 换行。另存为使用 UTF-8。无法完整编码的内容会被拒绝写入，而不会静默转换为问号。

## 恢复与边界

恢复草稿写入 Electron 用户数据目录的 drafts.json；开发启动使用项目内的独立 profile。连续编辑期间约每 400ms 提交最新快照，不要求停下输入后才保存。正常关闭会等待草稿状态落盘。强制结束或断电时，最后一次成功快照之后的极短输入仍可能丢失。

恢复文件损坏时保留原文件并报告错误，禁止静默覆盖该恢复文件；此时手动文件保存仍可用，新的恢复快照暂停写入。草稿没有加密，因此与其他本地编辑器草稿一样，应按个人本地数据保管。

外部变化按内容指纹检查，窗口重新获得焦点及可见时周期检测。检测不会替代保存时的再次校验。自动重载保留滚动位置，但复杂格式中的精确光标位置仍需继续改进。

## 验证

- 14 项文件层检查：多编码及 BOM/CRLF 往返、另存为、同长度外部修改、删除、并发旧基线、不可编码内容、临时写入失败与草稿持久化。
- 138 项真实编辑器界面回归：保留原界面行为，并覆盖保存、重开、输入与保存并发、只读失败、关闭保护、冲突处理、文件删除及恢复后保存。
- 3 项正常启动检查：空状态、新建保存和磁盘重读。
- 4 项跨进程恢复检查：直接结束第一个进程而不执行正常关闭清理，第二个进程提示并恢复有名和未命名草稿，随后保存。

系统打开/保存对话框在自动检查中使用固定路径与取消结果替代；真实系统对话框、完整中文输入法和全部目标 Windows 配置仍需要人工验收。

参考：[Node.js 文件接口](https://nodejs.org/api/fs.html)、[Electron 窗口关闭事件](https://www.electronjs.org/docs/latest/api/browser-window)、[iconv-lite 编码库](https://github.com/pillarjs/iconv-lite)。
