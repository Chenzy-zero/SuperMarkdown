# 编辑器技术验证原型

验证问题：在真实 Windows 桌面窗口中，可视编辑与源码编辑能否共享文档和撤销记录；修改正文时，既有的公式与 Mermaid 片段能否保留原始写法？

## 运行

可直接双击仓库根目录的 [启动SuperMarkdown.cmd](../../启动SuperMarkdown.cmd)。开发终端中也可在仓库根目录运行 `pnpm prototype`；后者要求终端能找到 pnpm。

左侧点击“打开文件夹”可选择真实本地目录，按需展开子目录。Markdown 默认可视编辑，TXT、代码、配置等其他文本文件按纯文本打开，未知扩展名及无扩展名文本也可读取。“刷新目录”重新列出当前文件夹；内置示例仍可单独展开试用。

原型读取真实文件，并支持实际创建空白 `.md` 文件；输入的正文修改仅保留在内存中，窗口关闭后丢失，当前不会将编辑结果保存回文件。

当前支持 UTF-8、带 BOM 的 UTF-16 及 GB18030/GBK 兼容文本。原型的单文件读取上限为 20 MB，不遍历符号链接和目录联接，二进制及不可解码文件不列入文本列表。这些是原型边界，不是最终需求的文件大小上限或编码范围。

## 试用步骤

1. 点击“打开文件夹”，选择一个包含 Markdown、TXT、代码的目录，展开子目录并打开文件，检查 Markdown 可视模式与其他文件纯文本模式是否符合预期。
2. 在“内置示例”的“开始写作.md”中用中文输入法写一段文字，输入标题或加粗语法，观察排版和光标行为。
3. 切换源码模式（按钮或 `Ctrl+Shift+M`），修改几行文字，再切回可视编辑；非 Markdown 文件固定使用纯文本模式。
4. 使用 `Ctrl+Z` / `Ctrl+Y`，观察能否撤销、重做切换模式前后的编辑。
5. 点击表格单元格，试用工具栏及编辑器的表格操作；记录不符合需求的行为。
6. 打开“内容保留样本.md”，只编辑普通正文，再切到源码，检查波浪线围栏和公式行尾空格是否保留。需要修改公式或流程图本身时使用源码模式。
7. 在文件标签页间切换，检查修改与编辑模式是否保留；Markdown 文档可切换左侧“大纲”尝试标题跳转。
8. 悬停正文超链接，在鼠标指针右下方查看实际 URL 或本地路径。浮层随鼠标移动，离开链接或滚动正文后收起，靠近窗口边缘时自动调整位置。点击原链接：网页交给默认浏览器，本地文本在工具中打开；相对路径按当前文件的位置解析。
9. 使用标签页的 `×` 关闭文档，或右键选择关闭其他、关闭右侧、关闭全部、复制路径、在文件夹中显示。关闭标签页不会删除磁盘文件；存在未保存修改时先确认是否放弃。
10. 打开文件夹后，点击左侧“新建 Markdown”，输入文件名；省略 `.md` 时自动补全。若要建在子目录中，右键该子文件夹，选择“新建 Markdown 文件”。文件实际创建在磁盘上，同名文件不会被覆盖。
11. 右键左侧文件，试用“打开”“在右侧打开”“复制完整路径”“在文件夹中显示”等操作。顶部文件标签页也支持右键“移到右侧显示”。
12. 在“显示布局”中选择“双文件并排”，分别编辑两篇文件；点击某侧正文后，模式切换、撤销和重做作用于该侧的文件。
13. 打开 Markdown，选择“预览 + 源码同步”：左侧排版正文、右侧源码均可直接编辑，另一侧即时更新，两边共用撤销与重做记录。关闭右侧窗格或选择“单文件”退出分屏。
14. 悬停顶部格式工具栏，检查提示完整显示在按钮下方；左右两侧的工具栏均使用同样的提示浮层。
15. 按 `Ctrl+W` 关闭当前文件，存在修改时先提示；分屏时先点击要关闭的一侧。同步布局的两侧属于同一篇文档，关闭时一并移除。没有打开文档时此快捷键保留窗口。
16. 切换 Markdown 可视编辑与源码，检查正文宽度和左右留白一致；分屏时同样按每个窗格的宽度居中显示。
17. 拖动分屏中间的竖线调整比例；双击恢复等宽。分隔条也可通过 Tab 聚焦，左右方向键调整，Home / End 移到两端可用宽度。拖动只调整布局，不修改正文。

## 自动检查

运行 `pnpm prototype:check`。它打开隐藏窗口，在真实编辑器中检查编辑、同步、历史、指定片段保留、文件目录与打开行为；生成 `.prototype-artifacts/report.json`、`.prototype-artifacts/editor.png` 与 `.prototype-artifacts/plain-text.png`。

检查使用项目内的临时样本目录，通过真实文件读取接口验证；原生文件夹选择对话框的交互尚需手动检查。

运行 `pnpm prototype:ux-check` 可加上本轮界面回归；`启动SuperMarkdown.cmd --verify` 使用同一检查，且启动不依赖 Node/pnpm 命令在 PATH 中。
